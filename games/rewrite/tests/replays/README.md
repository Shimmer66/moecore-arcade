# 八关输入回放

这些文件保存的是控制器输入，不是存档或游戏状态。测试从 `createRun` 的正常初始生命、武器和敌人开始，按 60 Hz 执行；不得写入坐标、血量、无敌时间、关卡编号或 Boss 状态来达成胜利。

## 格式

`schema: 2`，`difficulty` 为街机/经典/硬核，`duo` 为单人/双人。P1 和 P2 均选择 DeepSeek 娘。`expectation` 记录完整通关后的物理帧数、死亡数、剩余续关与关卡数。

`tape` 的每行是 `[持续帧数, P1 输入位, P2 输入位]`。输入位可组合：左1、右2、上瞄准/基地前进4、下/卧倒8、射击16、跳跃32、手雷64、定点瞄准128。跳跃与手雷是按下事件，必须只持续一帧；基地跳跃使用32、前进使用4，两者独立。

新增直选装备位：P/S/M/L/F/H 分别为 256/512/1024/2048/4096/8192。浏览器映射为 P1 数字 1–6、P2 数字键盘 4–9。只能选择已持有武器；规划器拾取新枪后主动选择，死亡后从保留库存选择，不依赖自动换枪。

P1 输入为负时是一项菜单操作：`-1` 只允许在过关后进入下一关，`-2` 只允许在失败且有余额时续关，`-3/-4` 只允许向离线的 P1/P2 分享队友的一命。测试会核对这些前置条件。浏览器重放通过实际键盘与按钮执行这些操作，只读取 DOM 中的物理帧计数来对齐输入。

## 重新生成与验证

- `npm --workspace @moecore/game-rewrite run record:campaign`：运行离线输入规划器，通过后更新回放文件；通常需要约一分钟。
- `npm --workspace @moecore/game-rewrite run test`：快速重放六种组合并核对八关结局，不在普通测试中执行规划搜索。
- `npm --workspace @moecore/web run test:e2e -- rewrite.spec.ts`：运行日常的短交互回归。
- 先运行 `npm run build`，再执行 `npm --workspace @moecore/web run test:e2e:rewrite-campaign`：在浏览器里用实际键盘重放到宿主结算，并检查重开/重新选角。长流程使用独立配置收集 `rewrite-campaign.flow.ts`，不进入默认短流程套件；本机完整十二种组合约需11分钟。

规划器会在克隆的未来状态上比较合法动作，再对真实对局施加所选输入。它能利用敌人和地形的精确信息，因此结果证明存在合法通关路线及流程连贯性，不代表真人平均难度、反应速度或体验优于其他游戏。回放在调平衡后失效时，应先调查失败原因，再重新生成，不能修改期望结果来伪装胜利。

| 普通双人 | 4 分 29 秒   | 7        | 0        |
| 经典单人 | 4 分 57 秒   | 3        | 0        |
| 经典双人 | 4 分 13 秒   | 7        | 0        |

| 硬核双人 | 4 分 15 秒   | 11       | 0        |

时间为规则模拟中的有效对局时间，包含基地推进，不包含菜单停留；并非真人通关时长。界面级证据以 Playwright 实际结果和结算截图为准。
