# 项目路线图

## 资料与当前范围

本仓库的初始化参考了提供的 `README.md` Monorepo 版和《AI看板娘小游戏开发方案书 V1.0》。
前者以合集为目标并建议消消乐优先，后者详细讨论弹珠乱斗。
本次落地前者的工作区结构，保留后者为后续玩法参考，不将附件中的排期、采购、上线或全部游戏开发建议视为本次执行任务。

当前已完成 Vue 宿主、一关消消乐和 AI 主题短局跑酷原型；正式内容量与公开发布验收仍未完成。
60 张消消乐与 72 张办公室候选素材用于本地开发预览；旧 400 张海洋素材保留归档。
原始文档和私密授权资料不进入站点产物。

## 阶段

| 阶段         | 交付目标                                             | 状态     |
| ------------ | ---------------------------------------------------- | -------- |
| 工程初始化   | 六个工作区包、Web 空状态、统一工具、基础测试、文档   | 已完成   |
| 消消乐原型   | Vue 界面、交换、连锁、目标、结算及有界重建           | 已实现   |
| 首个可玩版本 | 五关、教程、设置、本地进度、输入与设备适配           | 待实现   |
| 首次公开发布 | 素材审核、真实设备验收、可回退构建与部署             | 待安排   |
| 跑酷原型     | 短局交付、尾巴退件、干饭、上下文护盾、幻觉核查与爆发 | 已实现   |
| 合集扩展     | 逐项验证其他玩法，之后评估休息室                     | 候选方向 |

新增游戏不等于增加一个按钮。每一项都要有可玩的流程、独立规则和必要验收。
不为所有候选玩法承诺统一排期。

## 内容地图

| 内容               | 最小方向与关键约束                                         |
| ------------------ | ---------------------------------------------------------- |
| 消消乐             | 交换式三消；目标、步数和连锁由独立规则层管理               |
| 大肥鱼跑酷         | 带着真正可运行的小游戏穿过混乱办公室，拒绝追加说明后交付   |
| 弹珠乱斗           | 三对三回合制弹射；只以位置和出界判胜，无血量               |
| 翻牌挑战           | 十二张六对卡；翻第二张才计一次尝试，错误牌盖回前禁止第三张 |
| 合成小屋           | 同角色同等级徽章合成；不设计不同模型之间的升级链           |
| 躲躲乐             | 单角色移动避障；轻量判定区、受伤短暂无敌、失焦暂停         |
| 守住最后一个 Token | 固定路线与部署点；虚构能量，不连接真实 API 用量            |
| 三人小队           | 独立回合制技能与关卡；战斗属性不反向加入弹珠规则           |
| 休息室             | 至少两款游戏稳定后评估的合集展示空间，不单独计为一款游戏   |

## 共同约束

- 不以“AI 主题”推导必须接入大模型、聊天或生成式语音。
- 首版不做账号、联网、付费、抽卡、限制游玩次数的体力系统和跨游戏养成；跑酷的三颗心仅为局内生命。
- 原型可以使用自制占位，未核验素材不进入公开资源目录。
- 设置、角色和资源可以共享，关卡、技能、胜负与分数保持游戏独立。
- 确定性试跑只验证规则与程序操作下的时长，不替代真人试玩、留存、通关率和真机性能验收。

## 后续决策

上下文缓存与幻觉核查已融入首关；独立的上下文档案室、幻觉样板间和需求变更走廊仍是后续区域方向。
当前没有生成额外关卡入口，也没有把文字梗扩成多套难以理解的操作。

代码许可证、公开部署平台、角色素材来源与许可、目标测试设备和后续玩法优先级仍待确认。
这些事项不阻止当前使用自制占位搭建工程，但公开发布前应逐项处理。
