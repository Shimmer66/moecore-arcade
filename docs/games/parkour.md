# 大肥鱼跑酷：答案马上就到

Vue 3 跑酷，入口 `/#/games/parkour`。可选三条有终点的航线和一条无限计分航线。
DeepSeek 娘一路抢白饭、退回补充说明，把真正能玩的小游戏送到灯塔。
场景和互动台词是原创同人戏仿，不是官方设定或模型原话。
没有真实模型请求、账号、计费、联网生成或新引擎依赖。

## 本次重设计

最初的 480 米单关扩为三条独立航线，长度分别为 600、650、740 米。
第一关起速从 7.4 提至 9.8 米/秒，后两关起速更高；程序试跑第一关约 43 秒，
这是确定性输入的结果，不代表所有真人操作用时。
首次访问只有一句“吃白饭”质疑与一句回应；点击开跑或直接按空格后倒计时 0.6 秒。
失败后点“再来一局”或按空格重试当前关；通关后主按钮进入下一关，也可返回选关。
所有模式从开始即可选择，不设未说明的解锁门槛。重新进入游戏或刷新页面仍显示开场。
开跑时页面将操作按钮滚入视野；开场说明键盘与手势，首次遇到文档堆、横梁、纸团和假饭时给出短提示。

核心循环是：读清障碍、选择安全路线或奖励路线、把废话退回去、积攒一次爆发、完成交付。
新增内容必须改变操作或选择，不只增加梗字幕。

“吃白饭”在社区讨论中既是对涨价、延期或答题失误的调侃，也被二创画成真的吃白米饭。
游戏以“交付答案证明没白吃”为主线，饭碗路线是字面双关，不能把梗简化成单纯的饥饿设定。
参见 [LINUX DO 涨价讨论](https://linux.do/t/topic/2685093/1)、
[LINUX DO 答题失误讨论](https://linux.do/t/topic/2797049?page=9) 和
[LINUX DO 白饭形象讨论](https://linux.do/t/topic/2727836)。

| 关卡     | 长度   | 主要变化                                                   |
| -------- | ------ | ---------------------------------------------------------- |
| 白饭航线 | 600 米 | 先学跳、滑与甩尾，饭碗可选，终段取得答案后冲过纸堆         |
| 回音礁   | 650 米 | 五个补充喷口，其中两个会连发；及时退回第一张纸可让喷口停机 |
| 请求漩涡 | 740 米 | 七支往返更快、更远的队伍与更多问号饭，重在读路线和核验时机 |
| 无限航线 | 无终点 | 随机连续生成跳／滑障碍与白饭，跑得越远速度和分数越高       |

无限航线从 32 米处出现第一个障碍，速度由 10.4 米/秒逐渐提高，最高 18 米/秒。
玩家用跳跃和滑铲持续避障；每个随机障碍前仅有一枚 Token，高处真饭提供更快的算力补给，
攒满后可用一次爆发撞开障碍。
每隔若干障碍会穿插问号假饭和往返的“服务器繁忙”队伍；问号饭可滑过，队伍可跳过。
每跑满 500 米触发一次“大肥鱼没白吃”里程碑，加 250 分和 25 算力。
未充满时尾巴按钮保持不可用，避免无目标的甩尾。三次碰撞后按本局米数与分数结算，
本机单独保存无限航线的最佳分；没有终点、答案包或强制剧情暂停。

没有中途剧情弹窗、假装加载的停顿、强制答题或第四个技能按钮。

文案布局采用固定分区：区域名与场景短句留在 HUD，开场对白放在跑道上方；开跑后，
操作提示、事件梗台词和动作结果合并在角色旁的短气泡中，技能状态留在跑道下方。
开场明确标注说话者，避免把角色标签读成指令。
同一时间只显示一条优先级最高的事件反馈；场内只保留必要的物体提示和图像特效，
物体提示靠近边缘时向内对齐，不让整段对白或飘字遮住角色和跑道。

## 三个动作

开跑前可选 Low / High / Max 三档“思考强度”。这借用了
[DeepSeek 官方思考强度名称](https://api-docs.deepseek.com/guides/thinking_mode/)，
但游戏不调用模型：Low 跑速为原版 1.08 倍、回信慢镜 18 步；High 为原版速度、36 步；
Max 为原版 0.94 倍、60 步。选择保留到本次浏览器会话中的重开。三档使用同一关卡和三键操作，
以上数值只是游戏节奏，不代表真实模型的速度、准确率或 token 消耗。

| 动作 | 键盘           | 触屏                 | 规则                                          |
| ---- | -------------- | -------------------- | --------------------------------------------- |
| 跳跃 | Space / 上 / W | 按钮、轻点或上划赛道 | 新按压起跳，一次空中再跳，长按不连跳          |
| 滑铲 | 下 / S         | 按钮或下划           | 按住持续；按钮持续 0.8 秒；空中使用会快速下落 |
| 尾巴 | X / Shift      | 按钮或右划           | 未充满时回信/核查，充满时大肥鱼爆发           |

尾巴回信有效窗口 24 个真实步（0.4 秒），冷却 40 步；长按不会连续触发。
前方 3.4 米、与角色高度对应的判定区可以把纸团打回原补充喷口。
纸团必须真正飞回去才记一次退件、加 180 基础分和 30 算力。
喷口随后停止输出并显示“回音已停”；不能重复刷同一张纸。
成功回信自动获得 36 步（0.6 秒）短暂半速，不消耗算力。
纸团也能滑过、跳过或在爆发中撞散，回信不是唯一解。

算力充满 100 时，同一个尾巴按钮变为“大肥鱼出击”。
消耗全部算力，持续 132 步（2.2 秒），以 1.75 倍速度粉碎障碍；速度不会逐帧叠乘。
遇到密集障碍与移动队伍可以早用，保留到喷口前则会以爆发替代回信，存在时机取舍。

## AI 特征如何进入玩法

| 机制       | 玩家决策和反馈                                                                             |
| ---------- | ------------------------------------------------------------------------------------------ |
| 干饭补算力 | 高处真饭需要二段跳，奖励 35 算力和 120 基础分；不吃也能通关                                |
| 白饭二连   | 连续拿到两碗真饭且没有漏拿或碰撞，第二碗奖励 240 基础分；上下文未满时再补 1 格，无需新按键 |
| 上下文护盾 | 每个蓝 Token 增加 5 算力和 1 格上下文；存满 6 格自动挡一次碰撞，消耗缓存但不扣心           |
| 缓存中断   | 未存满时受伤清空上下文和连击；护盾使用后重新收集，不叠加多个护盾                           |
| 幻觉核查   | 灰色、问号、虚线框的饭标注“AI 生成 · 未核验”；尾巴核查或爆发清除获得 15 算力和 100 基础分  |
| 信了假饭   | 直接碰到未核验饭不掉心，但扣 20 算力并断连击；滑过则没有奖惩                               |
| 深度思考   | 回信成功后的短慢动作奖励，不再是额外资源按钮                                               |
| 服务器繁忙 | 四个带轮子的需求箱真实往返移动；不是读条，仍可跳过或爆发粉碎                               |
| 停止生成   | 最后拿到答案就充满尾巴，直接撞开说明书，把可运行的东西送出去                               |

这些是对 LLM 概念的游戏化转译。现实的上下文缓存并不是护盾，事实核查也不是物理击打；
不能把游戏数值当成真实模型能力比较或技术说明。

三颗心；普通受伤保护 72 步。连击每 8 次提升一级奖励倍数，最多 5 倍。
结算统计饭量、退件、核验、最高连击与有效时长；
一局分别达到两碗饭、两件退回、两次核验，可得到“干饭认证 / 退件高手 / 拒绝幻觉”的评价。
评价仅属于这一局，没有伪装成已实现的持久成就或跨游戏经济。

台词跟随事件，例如“已读，原路退回。”“查无此饭，已撤回。”
尾巴旁白承担反差笑点；没有声称已有独立尾巴骨骼动画、生成式语音或人格模型。

## 实现与生命周期

- `config/shift.ts`：三关长度、区域、速度、障碍、喷口、队伍和假饭编排。
- `rules/adventure.ts`：不可变状态、奖励与交互；复用已有固定 `1/60` 秒积分和 swept AABB。
- `config/story.ts`：原创事件文案与结尾评价。
- `ParkourGame.vue`：输入锁存、RAF、暂停、首次开场和一次性结算。
- `AnswerSeaStage.vue`：数据海背景、物体、收据、碎纸和触屏手势。

基础规则的默认终点仍是 1,200 米，用于已有物理回归；前三关分别显式设置
`finishDistance = 600 / 650 / 740`。无限航线复用相同物理，单独放开障碍生成范围，
按前方视野补充物体并清理已跑过的物体，不在 1,200 米处结束。
纸团和移动需求箱使用相对运动扫掠判定，不拿图片的透明边框当碰撞箱。

真实步管理技能窗口和有效时长，世界步管理物理、喷口预警与队伍。
慢动作跳过的步仍锁存短暂跳跃和尾巴窗口；暂停不推进任一时钟。
宿主的 `attempt` 每次重开递增，新访问重置为 1。卸载清除 RAF、键盘、手势和异步素材回调。
结果携带会话 ID，宿主拒绝过期或重复结果。拿到答案且抵达出口才算成功。

## 素材边界

`packages/assets/whale-runner` 保留用户提供的 72 张源 PNG、哈希及 WebP 运行图。
其中 70 张 RGBA，背景和菜单图为 RGB；原始生成提示词不是已校准动画规格。
`scripts/prepare-whale-assets.py` 以 Pillow 裁掉明显透明边距、等比例缩放并统一角色底线，
不修改原 PNG。游戏只预载角色动作、表情和少数特效，并用 `Image.decode` 检查。
独立姿态仍是原型级对齐，不声称已经成为美术精修的连续动画。

三张背景位于 `packages/assets/resources/`：首关 `answer-sea.png` 是蓝色数据海；
第二关 `echo-reef.webp` 参考首关画风，生成紫色纸带与折纸礁岛；
第三关 `request-vortex.webp` 参考同一画风，生成青蓝数据海与远处请求漩涡。
三张提示词均要求宽横幅、清晰视线、无角色、文字或前景跑道；后两张由内置 GPT Image 生成后转为 WebP。
游戏使用自制 `rice-bowl.svg` 饭碗；旧 `canteen.svg` 留作未使用素材。来源登记在 `packages/assets/CREDITS.md`。
没有从网上复制梗图或游戏美术，也不热链图片。
当前预览和构建会载入角色动作与表情；海面跑道、补充喷口和灯塔由 CSS / SVG 绘制。
旧 400 张海洋素材保留归档。素材审核状态未因这次玩法改动而改变。

## 验证与限制

规则覆盖原有 512 种子基础回归、第一关 32 种子完整试跑、后两关可达路线，
以及无限航线超出 1,200 米后继续生成、计分和有界物体数量；还测试回信窗口、冷却、
纸团去重、二段跳饭碗路线、无饭路线、护盾消耗、假饭核验、移动队伍与精确终点。
浏览器测试覆盖桌面与手机视口的选关、无限计分结算、正常输入、暂停、快速重试、跨游戏切换、320px 布局和首关完整交付。
浏览器测试检查画面布局与图像加载，生产构建会载入选用的角色图片。

仅在本地保存最佳分；尚未实现音效、未完局进度保存或真人难度调研。
程序试跑通过不等于已经证明“有趣”，移动视口模拟也不等于真机性能验收。
