# 大肥鱼跑酷：答案马上就到

Vue 3 短局跑酷，入口 `/#/games/parkour`。DeepSeek 娘穿过自己生成的混乱办公室，
把真正能玩的小游戏交给访客。场景和互动台词是原创同人戏仿，不是官方设定或模型原话。
没有真实模型请求、账号、计费、联网生成或新引擎依赖。

## 本次重设计

把原来的 1,200 米、三屏开场和两个强制阅读点，替换成 480 米连续短局。
目标是约 45–60 秒；这是确定性试跑的验证目标，不是所有真人操作下的保证。
首次访问只有一句需求与一句回应；点击开跑后倒计时 0.6 秒。
失败后立即重开，不再重复开场。重新进入游戏或刷新页面仍显示开场。

核心循环是：读清障碍、选择安全路线或奖励路线、把废话退回去、积攒一次爆发、完成交付。
新增内容必须改变操作或选择，不只增加梗字幕。

| 区域                     | 内容                                                     |
| ------------------------ | -------------------------------------------------------- |
| 0–78 米，食堂分部        | 文档、横梁、低处 Token 与需要二段跳的高处饭碗            |
| 78–250 米，补充说明科    | 打印机预警、移动纸团、限时尾巴回信和首次幻觉核查         |
| 250–406 米，服务器排队区 | 真正往返移动的需求队伍，穿插文档、横梁和未核验食物       |
| 406–480 米，交付出口     | 取得答案、尾巴充满、密集文档可连续粉碎，抵达出口自动交付 |

没有中途剧情弹窗、假装加载的停顿、强制答题或第四个技能按钮。

文案布局采用固定分区：部门名与场景短句留在 HUD，访客与 DeepSeek 娘的对白放在跑道上方，
动作结果与技能状态放在跑道下方。开场明确标注说话者，避免把角色标签读成指令。
同一时间只显示一条优先级最高的动作反馈；场内只保留必要的物体提示和图像特效，
物体提示靠近边缘时向内对齐，不让整段对白或飘字遮住角色和跑道。

## 三个动作

| 动作 | 键盘           | 触屏                 | 规则                                          |
| ---- | -------------- | -------------------- | --------------------------------------------- |
| 跳跃 | Space / 上 / W | 按钮、轻点或上划赛道 | 新按压起跳，一次空中再跳，长按不连跳          |
| 滑铲 | 下 / S         | 按钮或下划           | 按住持续；按钮持续 0.8 秒；空中使用会快速下落 |
| 尾巴 | X / Shift      | 按钮或右划           | 未充满时回信/核查，充满时大肥鱼爆发           |

尾巴回信有效窗口 18 个真实步（0.3 秒），冷却 40 步；长按不会连续触发。
前方 2.8 米、与角色高度对应的判定区可以把纸团打回原打印机。
纸团必须真正飞回去才记一次退件、加 180 基础分和 30 算力。
打印机随后停止输出并吐出“退订成功”的收据；不能重复刷同一张纸。
成功回信自动获得 36 步（0.6 秒）短暂半速，不消耗算力。
纸团也能滑过、跳过或在爆发中撞散，回信不是唯一解。

算力充满 100 时，同一个尾巴按钮变为“大肥鱼出击”。
消耗全部算力，持续 132 步（2.2 秒），以 1.75 倍速度粉碎障碍；速度不会逐帧叠乘。
遇到密集文档与移动队伍可以早用，保留到打印机前则会以爆发替代回信，存在时机取舍。

## AI 特征如何进入玩法

| 机制       | 玩家决策和反馈                                                                            |
| ---------- | ----------------------------------------------------------------------------------------- |
| 干饭补算力 | 高处真饭需要二段跳，奖励 35 算力和 120 基础分；不吃也能通关                               |
| 上下文护盾 | 每个蓝 Token 增加 5 算力和 1 格上下文；存满 6 格自动挡一次碰撞，消耗缓存但不扣心          |
| 缓存中断   | 未存满时受伤清空上下文和连击；护盾使用后重新收集，不叠加多个护盾                          |
| 幻觉核查   | 灰色、问号、虚线框的饭标注“AI 生成 · 未核验”；尾巴核查或爆发清除获得 15 算力和 100 基础分 |
| 信了假饭   | 直接碰到未核验饭不掉心，但扣 20 算力并断连击；滑过则没有奖惩                              |
| 深度思考   | 回信成功后的短慢动作奖励，不再是额外资源按钮                                              |
| 服务器繁忙 | 四个带轮子的需求箱真实往返移动；不是读条，仍可跳过或爆发粉碎                              |
| 停止生成   | 最后拿到答案就充满尾巴，直接撞开说明书，把可运行的东西送出去                              |

这些是对 LLM 概念的游戏化转译。现实的上下文缓存并不是护盾，事实核查也不是物理击打；
不能把游戏数值当成真实模型能力比较或技术说明。

三颗心；普通受伤保护 72 步。连击每 8 次提升一级奖励倍数，最多 5 倍。
结算统计饭量、退件、核验、最高连击与有效时长；
一局分别达到两碗饭、两件退回、两次核验，可得到“干饭认证 / 售后专家 / 拒绝幻觉”的评价。
评价仅属于这一局，没有伪装成已实现的持久成就或跨游戏经济。

台词跟随事件，例如“已读。并弹回。”“查无此饭。撤回，立刻撤回。”
尾巴旁白承担反差笑点；没有声称已有独立尾巴骨骼动画、生成式语音或人格模型。

## 实现与生命周期

- `config/shift.ts`：短局长度、部门、基础速度与带小幅种子变化的障碍编排。
- `rules/adventure.ts`：不可变状态、奖励与交互；复用已有固定 `1/60` 秒积分和 swept AABB。
- `config/story.ts`：原创事件文案与结尾评价。
- `ParkourGame.vue`：输入锁存、RAF、暂停、首次开场和一次性结算。
- `OfficeStage.vue`：图片、视差、物体、收据、碎纸和触屏手势。

基础规则的默认终点仍是 1,200 米，用于已有物理回归；本游戏显式设置 `finishDistance = 480`，
替换其障碍编排，不生成第二套旧玩法入口。正式游戏只有当前这套规则和组件。
纸团和移动需求箱使用相对运动扫掠判定，不拿图片的透明边框当碰撞箱。

真实步管理技能窗口和有效时长，世界步管理物理、打印机预警与队伍。
慢动作跳过的步仍锁存短暂跳跃和尾巴窗口；暂停不推进任一时钟。
宿主的 `attempt` 每次重开递增，新访问重置为 1。卸载清除 RAF、键盘、手势和异步素材回调。
结果携带会话 ID，宿主拒绝过期或重复结果。拿到答案且抵达出口才算成功。

## 素材边界

`packages/assets/whale-runner` 保留用户提供的 72 张源 PNG、哈希及 WebP 运行图。
其中 70 张 RGBA，背景和菜单图为 RGB；原始生成提示词不是已校准动画规格。
`scripts/prepare-whale-assets.py` 以 Pillow 裁掉明显透明边距、等比例缩放并统一角色底线，
不修改原 PNG。运行图约 9.3 MB，游戏只预载需要的资源并用 `Image.decode` 检查。
独立姿态仍是原型级对齐，不声称已经成为美术精修的连续动画。

新增自制 `rice-bowl.svg` 与 `canteen.svg` 用于特定游戏道具，来源登记在 `packages/assets/CREDITS.md`。
没有从网上复制梗图或游戏美术，也不热链图片。
原 72 张候选素材只在开发环境预览，正式构建继续用自制几何角色和道具。
旧 400 张海洋素材保留归档。素材审核状态未因这次玩法改动而改变。

## 验证与限制

规则覆盖原有 512 种子基础回归，以及新的 32 次短局完整试跑；还测试回信窗口、冷却、
纸团去重、二段跳饭碗路线、无饭路线、护盾消耗、假饭核验、移动队伍与精确终点。
浏览器测试覆盖桌面与手机视口的正常输入、暂停、快速重试、跨游戏切换、320px 布局和完整交付。
开发模式另行检查候选图片解码和画面呈现；生产 E2E 不会加载候选图片。

尚未实现音效、额外关卡、进度保存或真人难度调研。
程序试跑通过不等于已经证明“有趣”，移动视口模拟也不等于真机性能验收。
