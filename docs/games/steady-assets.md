## 1. 搞怪方向

**脸还在安慰你，身体已经在后悔。**

让现有物理关系负责制造笑点：人戴锅所以会被磁铁拖走；气球把人提起来，GPT 只好倒挂着接；用户真的到了，姿势却像一件横着送来的快递。

统一表达：

- GPT 有鲜明的前后反差：自信营业、受力硬撑、瞬间破防、事后假装从容。
- 用户反应慢半拍：身体在失控，脸还像赶地铁时一样疲倦。
- 道具保留功能辨识：锅有铁质高光，气球轻而膨胀，磁铁两极清楚，蹦床的倾斜面可见。
- 原画的小失衡用来表达受力，玩法区域中的位置与碰撞仍要清楚。
- 强烈鬼脸放在短反应插片；小尺寸角色保留大轮廓与两三处关键表情。
- 笑点由画面本身成立，文案由程序随后添加。

三个验收例子：

1. 看“锅在赶路，人是赠品”，能立刻找到锅、头盔、牵引方向和用户的无奈表情。
2. 看“上天接人”，能认出气球提供向上拉力、磁铁吸锅、GPT 在上面接应。
3. 看“承诺说早了”，去掉台词后仍能看出嘴在微笑、眼睛和身体已经慌了。

## 3. 哪些应继续用程序绘制

| 内容                       | 建议                                   | 原因                                                       |
| -------------------------- | -------------------------------------- | ---------------------------------------------------------- |
| 绳索、磁力场、路线虚线     | SVG / Canvas 动态绘制                  | 必须随位置、连接和通断电实时变化                           |
| 蹦床碰撞面与框架           | 保留代码图形，重画皮肤；弹面与支架分层 | 角度、长度和落点要对应真实碰撞，材质可用淡紫橡胶与塑料表达 |
| 桌面、房间边界、接应网     | 保留独立代码层                         | 背景图片里烘焙这些结构会造成视觉与判定错位                 |
| 选中框、拖拽把手、旋转按钮 | 原生 SVG / HTML / CSS                  | 保持缩放、键盘焦点和触摸区域                               |
| 名称、对白、提示、得分     | 程序文字                               | 可读、可更新，也能调整字号                                 |
| 汗滴、短促碰撞星、磁场明灭 | 少量代码粒子或变换                     | 容易控制时长，不需要大量重复图片                           |

蹦床皮肤建议：弹面有一点像摊开的软饼，但仍保留明确的平面与支架；用橡胶/塑料质感，避免画成另一个也应被磁铁吸走的铁器。这是代码重画说明，不占图片提示词数量。

## 5. 分层、尺寸与一致性

### 5.1 不能烘焙成一张的组合

- 用户身体、锅帽、气球本体、绳子四层独立。
- GPT 身体与接应网独立；手掌不能与用户永久画在一起。
- 磁铁本体与磁力场独立，通断电复用一个本体。
- 组合关键画面只作试稿、封面或反应构图参考，不当作可以拆开操作的素材。
- 需要动作时使用独立姿态或分层变换；本包不声称能生成已对齐的连续动画图集。

### 5.2 输出建议

- 角色、道具、反应图：请求单张 1024×1024，透明 RGBA PNG。
- 背景：单张 1024×1024，不透明，进入游戏时裁切到房间比例。
- 封面与组合试稿：1536×1024 横图。
- 工具返回后实际检查尺寸和 alpha，不能仅凭提示词认为已经满足。
- 核心运行图不包含文字、网格背景、水印或贴纸白边。
- 首轮先做静态关键姿态，约定姿态以外的晃动、拉伸、旋转由程序处理。

### 5.3 接入时必须检查

当前用户碰撞半径为 19 个逻辑单位，锅半径 22；手机上角色较小。复杂发丝、表情小字与密集装饰不会带来有效信息。

所有用户姿态应按同一身体中心、头部大小和脚底参考对齐。锅帽按头顶接点对齐，气球按底部结对齐。GPT 的接应点以双手中点为准，地面与天花板姿态分别标注，不直接拿整张图片外框当锚点。

生成模型不会可靠输出精确锚点。选图后应在工具中对齐、记录锚点，再检查它们与现有碰撞及接应区域的关系。不要为了让大图好看而静默扩大物理判定。

### 5.4 参考图使用

01 使用已有 GPT 全身图建立实验室版本，移除纸堆并让双手空出。其他 GPT 图片优先以上一步选中的 01 为风格和身份参考。

05 建立用户基准；06–08 和用户反应图沿用它。09 建立铁锅造型，10 沿用同一材质与锅耳。

把 JSON 中的参考文件或已选素材附给生成工具。仅在提示词里写一个文件名并不会自动提供参考图。`proposed_path` 是建议的项目落盘位置，也不是图片工具的保存路径参数；具有 `generated_path` 的四条记录已实际生成，其余仍为计划。

## 6. 表情与游戏状态的映射

| 画面                | 可依据的现有状态             | 接入建议                                    |
| ------------------- | ---------------------------- | ------------------------------------------- |
| GPT 待接            | 布置阶段、普通运行           | 常驻姿态                                    |
| 用户下坠 / 上升     | 用户垂直速度的正负           | 设小阈值避免速度接近零时频繁换图            |
| 锅帽                | 用户 metal 状态              | 在身体之上叠加同一锅帽                      |
| 天花板 GPT          | layout.side                  | 改用专门姿态，手掌对齐上方接应点            |
| 成功与失败表情      | scene.phase                  | 结算切换，保留主体可读性                    |
| GPT 硬撑 / 惊慌插片 | 用户与接应点距离、接近速度等 | 需要补演出触发和消退规则，目前并非现成功能  |
| 用户磁力特写        | 磁力作用与实际位移           | 只作一次短反应，不覆盖正在操作的目标        |
| 某张蹦床压缩        | 当前只有累计 bounces         | 需补具体命中道具 ID，不能让所有蹦床同时乱抖 |

建议反应插片停留约 0.4–0.8 秒，但不暂停或遮住主要操作。减少动态效果开启时，保留静态表情反馈即可。上述时长是待试玩调整的建议。
