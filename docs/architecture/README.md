# 架构与包边界

## 当前结构

`apps/*` 是可启动或部署的应用；`games/*` 是可被应用装载的游戏；`packages/*` 是共享源码包。
首版只部署 `apps/web`，没有独立游戏站点、业务后端或 npm 包发布流程。

| 包                     | 当前职责                           | 后续边界                       |
| ---------------------- | ---------------------------------- | ------------------------------ |
| `@moecore/web`         | 应用启动、首页空状态、游戏注册位置 | 组装服务与会话，不实现游戏规则 |
| `@moecore/game-match3` | 原型配置与棋盘类型                 | 独立实现三消规则、关卡和场景   |
| `@moecore/game-sdk`    | 公共生命周期、设置、存储和结果类型 | 不依赖 Phaser 或具体玩法       |
| `@moecore/characters`  | 角色候选 ID、展示名、素材状态      | 不定义跨游戏统一战力           |
| `@moecore/assets`      | 自制资源及显式 URL 映射            | 只接入可公开分发资源           |
| `@moecore/storage`     | 按游戏生成版本化存储键             | 后续增加持久化适配和异常降级   |

内部包的 `exports` 直接指向 TypeScript 源码，由 Vite 统一编译。
不为这些包单独创建构建产物；Node 工具复用或独立发布需求出现后再调整。

## 依赖规则

```text
apps/web -> games/* -> packages/*
apps/web ------------> packages/*
```

公共包只能依赖其他公共包，不得反向依赖应用或游戏。游戏不得依赖其他游戏或应用。所有依赖保持无环。
跨包只能使用包名及公开子路径，在调用方清单中声明 `workspace:*`。
不使用指向兄弟包源码的 TypeScript 路径别名。

`scripts/check-workspace.mjs` 检查清单、公开导出、显式源码导入和内部依赖图；
ESLint 同时限制反向导入。当前检查面向本仓库约定的 TypeScript ESM 源码与显式字符串导入，不是任意动态代码的安全沙箱。
工具配置可以复用根级配置，不作为运行时源码跨包导入。

## 游戏接入契约

正式类型定义位于 `packages/game-sdk/src/index.ts`：

- `GameModule`：游戏 ID、标题和异步 `mount`。
- `GameContext`：宿主创建的会话 ID、终止信号、设置、限定命名空间的存储和回调。
- `GameInstance`：暂停、恢复、尺寸变化、设置更新及销毁。
- `GameResult`：游戏与会话 ID、结果、有效时长和本游戏统计。

当前仅有类型契约，宿主执行器与游戏实例尚未实现。以下是后续实现要求：

1. 同一时刻最多一个活动游戏实例；显式动态导入，避免一次加载所有玩法。
2. 切换、重开或退出时终止旧会话，销毁实例，并释放引擎、音频、计时器和监听器。
3. `destroy` 可重复调用；加载失败或收到终止信号时清理已创建资源。
4. 动态导入无法取消时忽略过期结果；不能把旧实例挂到新容器。
5. 核对游戏 ID、会话 ID 和结束标记，同一局只处理一次结算。
6. 暂停覆盖规则、引擎、输入与计时。恢复焦点不能覆盖用户主动暂停。
7. 不承诺刷新续玩，退出未完成对局前明确提示。

分数与技能由各游戏定义，不能将不同游戏成绩直接合成统一排名。

## 角色和资源

角色候选与可用图片分开管理。登记角色名称不代表已经取得相应图像。
`packages/assets/resources` 只存自制或已审核资源，`CREDITS.md` 是公开署名入口。
运行资源通过显式映射导入，由宿主构建；不依赖其他包的 `public` 目录自动发布，也不热链第三方图片。

`apps/web/public` 同样属于发布资源目录；即便没有被页面引用，文件仍可能进入产物。
完整资源审核和产物扫描尚未实现，正式发布前需补齐，不能用清单单元测试代替授权审核。

## 本地数据

当前已定义：

```text
moecore:settings:v1
moecore:game:<encoded-game-id>:v1:<encoded-record-key>
```

`createGameStorageKey` 会编码两个可变字段，避免分隔符混入导致键碰撞。
它目前只生成键，不读写浏览器存储。

后续宿主向游戏提供限定命名空间的 `GameStorage`；各游戏负责自己的数据校验和迁移。
本地存储不可用时降级到会话内存并提示用户；损坏记录不能阻止游玩。
不静默清空其他游戏的进度，不记录密钥、账号信息或真实模型用量。

## 有意后置

Phaser 在首个实际场景落地时声明依赖并验证版本；物理玩法按需要启用其 Matter 集成。
暂不建设通用引擎封装、通用 UI 包、任务缓存平台、微前端、联网服务或跨游戏经济系统。
第二款游戏产生真实复用需求后，再抽取共同能力。
