# 架构与包边界

## 当前结构

`apps/*` 是可启动或部署的应用；`games/*` 是可被应用装载的游戏；`packages/*` 是共享源码包。
首版只部署 `apps/web`，没有独立游戏站点、业务后端或 npm 包发布流程。

| 包                          | 当前职责                                      | 后续边界                     |
| --------------------------- | --------------------------------------------- | ---------------------------- |
| `@moecore/web`              | Vue 游戏列表、动态加载、暂停、重开与结算      | 不实现游戏规则               |
| `@moecore/game-arena`       | 三关平台规则、生成事故、撤销救场和角色输入    | 不导入其他游戏或应用代码     |
| `@moecore/game-match3`      | Vue 棋盘、纯 TypeScript 规则、原型关卡        | 不导入其他游戏或应用代码     |
| `@moecore/game-parkour`     | Vue 跑道、固定步长规则、AI 主题交互与事件台词 | 不导入其他游戏或应用代码     |
| `@moecore/game-sokoban`     | 五关推箱子、路径输入、撤销与关卡切换          | 不导入其他游戏或应用代码     |
| `@moecore/game-whale-queue` | 16×16 队列移动、种子地图与灵感收集            | 不导入其他游戏或应用代码     |
| `@moecore/game-rewrite`     | 模型战争的角色选择、跳跃射击与能力组合        | 不导入其他游戏或应用代码     |
| `@moecore/game-sdk`         | 组件定义、props、事件与结果类型               | 仅类型契约，不创建引擎实例   |
| `@moecore/characters`       | 角色候选 ID、展示名、素材状态                 | 不定义跨游戏统一战力         |
| `@moecore/assets`           | 站点标识、首页封面与各游戏素材 URL 映射       | 只接入已审核或明确标记的资源 |
| `@moecore/storage`          | 按游戏生成版本化存储键                        | 后续增加持久化适配和异常降级 |

内部包的 `exports` 直接指向 TypeScript / Vue 源码，由 Vite 统一编译。
不为这些包单独创建构建产物；Node 工具复用或独立发布需求出现后再调整。

Vue 3 用于宿主及游戏界面；游戏规则通过 `./rules` 独立导出，不导入 Vue、图片或浏览器 API。
SDK 的 `Component` 是类型依赖，不包含 Vue 运行时代码。多人分别开发自己的游戏包，共用组件契约。

## 依赖规则

```text
apps/web -> games/* -> packages/*
apps/web ------------> packages/*
```

公共包只能依赖其他公共包，不得反向依赖应用或游戏。游戏不得依赖其他游戏或应用。所有依赖保持无环。
跨包只能使用包名及公开子路径，在调用方清单中声明 npm 兼容的本地 workspace 引用。
不使用指向兄弟包源码的 TypeScript 路径别名。

`scripts/check-workspace.mjs` 检查清单、公开导出、显式源码导入和内部依赖图；
ESLint 同时限制反向导入。检查覆盖 `.ts` 和 Vue SFC 的脚本，解析显式字符串导入，不是任意动态代码的安全沙箱。
工具配置可以复用根级配置，不作为运行时源码跨包导入。

## 游戏接入契约

推演对决新增两个可选字段：`GameProps.restartMode`（`replay` / `select`），以及 `GameResult.reselectLabel`。提供后者的游戏在宿主结算中显示重新选择按钮；宿主创建新的会话并传递 `select`，普通再战传递 `replay`。其他游戏可忽略这两个字段。角色选择仅由本游戏维护，宿主不读取格斗规则。

正式类型定义位于 `packages/game-sdk/src/index.ts`：

- `GameDefinition`：游戏 ID、标题和 Vue 根组件。
- `GameProps`：宿主创建的 `sessionId`、本次访问的 `attempt`、`paused` 和设置。
- `GameEvents`：`finish` 携带结果，`exit` 请求退出。
- `GameResult`：游戏与会话 ID、结果、有效时长、摘要和统计；可选 `story` 提供结尾标题、正文和图片 URL。

`GameHost.vue` 使用 `<component :is="definition.component" :key="sessionId">` 装载游戏。
不为游戏再调用 `createApp`，不保留旧的手动挂载与销毁接口，也不使用 KeepAlive 缓存未结束的对局。

1. 注册表提供显式动态导入，首页只显示实际注册的游戏；同一时刻最多一个游戏组件。
2. 重开更换 `sessionId` 并增加 `attempt`；新访问从 1 开始。退出或切换卸载组件，游戏在 `onUnmounted` 中释放计时器、动画帧和监听。
3. 宿主通过加载版本号拒绝过期导入；组件通过清理自身回调避免修改下一局。
4. 宿主核对结果的游戏 ID 与会话 ID，拒绝过期或重复结算。
5. `paused` 为真时游戏停止输入、动画推进及计时。窗口重新获得焦点不自动恢复。
6. 宿主的退出、重开按钮会在未完成对局时请求确认；刷新与浏览器导航不保留对局，不支持续玩。当前 Logo 与顶部站内导航直接修改 hash，仍可绕过确认，这是待修缺口。
7. 加载失败提供重新加载；路由保留游戏 ID，完整刷新后重新尝试模块加载。

分数与技能由各游戏定义。宿主显示游戏传入的摘要，不解释消消乐专属的统计字段，也不合成统一排名。
六款已注册游戏共用同一宿主；新增游戏实现相同 props / 事件、声明依赖并添加注册项，不复制宿主。
跑酷只在首次访问显示一句开场，`attempt > 1` 直接进入短倒计时；局内不插入阅读暂停。
开场、倒计时及宿主暂停不增加有效对局时长。游戏可以忽略 `attempt`，消消乐仍正常初始化新棋盘。
宿主只显示游戏提供的结尾，不参与游戏的剧情条件判定。

## 角色和资源

角色候选与可用图片分开管理。登记角色名称不代表已经取得相应图像。
`packages/assets/resources` 存放站点占位资源，`packages/assets/match3` 存放消消乐开发素材；
`CREDITS.md` 是公开署名和审核状态入口。
`packages/assets/parkour` 的旧 400 张素材保留归档。当前办公室跑酷通过
`@moecore/assets/whale-runner` 加载新素材的 WebP 运行图。首页跑酷封面仍复用旧包中的单张角色姿态；归档描述不表示旧包完全没有运行引用。
运行资源通过显式映射导入，由宿主构建；不依赖其他包的 `public` 目录自动发布，也不热链第三方图片。

`apps/web/public` 同样属于发布资源目录；即便没有被页面引用，文件仍可能进入产物。
消消乐、跑酷、推箱子与鲸鲸长队使用的生成素材在开发和公开试玩构建中均加载，首页通过 `HOME_ART` 复用部分角色图。模型战争使用组件内 SVG 绘制角色和场景。
项目所有者已同意自创素材用于公开试玩；`generated-pending-review` 仍表示品牌、角色形象及成品质量待复核，详情见 [素材清单](../../packages/assets/CREDITS.md)。构建成功不改变审核状态。
完整资源审核和产物扫描尚未实现，正式发布前需补齐，不能用清单单元测试代替授权审核。

## 共享视觉契约

`apps/web/src/styles.css` 提供 `--ui-*` 颜色、表面和圆角变量，游戏组件通过 CSS 继承使用，不能为读取变量而导入应用源码。保留的 `--home-*` 变量是既有游戏样式的兼容别名。

导航与页脚由 `App.vue` 管理，暂停、结算、重开确认由 `GameHost.vue` 管理；各游戏负责棋盘、场景和玩法控制。新游戏应按 [UI 规范](../ui-guidelines.md) 接入外围控件，游戏美术可保留独立主题。

首页封面映射目前位于 `HomeView.vue`，与游戏注册表分开维护。新增注册项不自动获得专属封面。

## 本地数据

当前已定义：

```text
moecore:settings:v1
moecore:game:<encoded-game-id>:v1:<encoded-record-key>
```

`createGameStorageKey` 会编码两个可变字段，避免分隔符混入导致键碰撞。
它目前只生成键，不读写浏览器存储。

后续宿主向游戏提供限定命名空间的 `GameStorage`；各游戏负责自己的数据校验和迁移。
本地存储不可用时降级到会话内存并提示用户；损坏记录不能阻止游玩。
不静默清空其他游戏的进度，不记录密钥、账号信息或真实模型用量。

## 有意后置

当前不引入 Phaser 或其他游戏引擎；未来物理玩法是否需要物理库，以该玩法的实际需求单独评估。
暂不建设通用引擎封装、通用 UI 包、任务缓存平台、微前端、联网服务或跨游戏经济系统。
继续根据多个游戏已出现的实际复用需求抽取共同能力，避免为候选玩法预建框架。
