# 《星尘远征》完整战斗与待机音效方案

日期：2026-10-05

## 一、现状与问题

当前仅实现了承太郎与 DIO 的连打喊声、合成拳击节奏及暂停清理：

- 连打持续 10 秒，每 300ms 触发一次喊声节拍。
- 没有授权录音时，使用本机语音合成作为临时回退。
- `masterVolume` 为零、游戏暂停或组件卸载时停止播放。

主要缺口：

- 普通攻击、重击、替身技、防御、受击、倒地与 K.O. 没有完整音效。
- 入场召唤、替身面板、`FIGHT`、换人、队伍击破与复活没有声音。
- 待机、场景环境和角色专属能力缺少音频表现。
- Web Audio 逻辑仍在游戏组件内，无法集中管理并发、暂停、音量和清理。
- 除连打外，没有纯函数音频事件映射及对应单元测试。

## 二、设计目标

1. 每个重要可见动作都有清晰、可辨认且不过度嘈杂的声音反馈。
2. 普通攻击、替身攻击、格挡和受击仅凭声音即可区分。
3. 四名主角与三名主要首领具有独立的招牌音色。
4. 待机声音低频、稀疏，不与战斗提示争夺注意力。
5. 暂停、静音、离局和重开不会遗留语音、循环声或 AudioNode。
6. 不使用动画原声；语音采用自制或已授权素材，本机语音仅作回退。

## 三、音频架构

新增以下模块：

- `games/stardust/src/audio/types.ts`
  - 定义 `StardustAudioEvent`、音频总线和音层类型。
- `games/stardust/src/audio/cues.ts`
  - 纯函数，将游戏事件映射为合成音层、样本 ID 和字幕。
- `games/stardust/src/audio/engine.ts`
  - 管理一个 `AudioContext`、音频总线、节点生命周期、样本缓存和并发限制。
- `games/stardust/src/audio/controller.ts`
  - 接收战斗事件，执行节流、角色专属映射、循环声启动/停止和暂停同步。
- `packages/assets/stardust/audio/`
  - 存放已授权或项目自制的 `.ogg` / `.wav` 文件、清单和来源说明。

音频总线：

- `master`：遵循宿主 `masterVolume`。
- `sfx`：拳脚、格挡、受击、UI 和环境交互。
- `voice`：欧拉、木大、角色短句。
- `ambience`：低音量场景环境和待机循环。

## 四、完整事件清单

### 1. 界面与入场

| 事件           | 音效                                 |
| -------------- | ------------------------------------ |
| 模式切换       | 短促机械切换音                       |
| 角色选择       | 轻量确认音，角色间音高略有区别       |
| 开始游戏       | 低频冲击与上扬提示                   |
| 替身召唤       | 低频能量涌入、空气撕裂与角色专属尾音 |
| 替身面板出现   | 金属卡片展开音                       |
| `FIGHT`        | 双层重击与短促爆发                   |
| 下一名敌人入场 | 接力提示音                           |
| 队伍击破       | 三段上扬胜利提示                     |

### 2. 待机与移动

| 事件     | 音效                                         |
| -------- | -------------------------------------------- |
| 普通待机 | 每 4–7 秒随机一次极轻服装或姿态声            |
| 替身待机 | 很低音量的角色专属能量嗡鸣，限制同时最多两个 |
| 步行     | 左右脚交替的短促落地声                       |
| 快速移动 | 更密集但音量较低的脚步                       |
| 转身     | 轻微布料或空气声                             |

当前游戏尚未实现跳跃；跳跃、腾空和落地音效待动作机制接入后启用，不伪造不存在的事件。

| 必杀起手 | 能量上升、短暂抽走环境声         |

| 格挡     | 金属/能量碰撞声                  |
| 受击     | 与攻击声分离的身体反馈           |
| 倒地     | 低频落地与轻微碎屑声             |
| K.O.     | 短静音后播放重击与裁决音         |
| 复活     | 由低到高的恢复音                 |

### 4. 角色专属音色

- **承太郎 / 白金之星**
  - 低沉拳击、精确金属点击、欧拉喊声。
  - 时停启动：环境骤停、低频脉冲。
  - 时停期间：极低的心跳与钟摆质感。
  - 时间恢复：集中释放积压命中声。
- **花京院 / 绿色法皇**
  - 绿宝石飞射使用玻璃与能量弹音色。
  - 法皇触须使用弹性甩动与细金属声。
- **阿布德尔 / 红色魔术师**
  - 火焰点燃、燃烧循环、爆燃命中。
  - 待机仅保留很轻的火焰噼啪声。
- **波鲁那雷夫 / 银色战车**
  - 剑刃出鞘、刺击、挥砍和格挡金属声。
  - 高速攻击使用短促连续剑风。
- **荷尔·荷斯 / 皇帝**
  - 枪声使用原创合成层，不复刻影视枪声。
  - 弯曲弹道加入左右声像移动。
- **瓦尼拉·艾斯 / 亚空瘴气**
  - 人形状态使用沉重装甲与低频呼吸。
  - 虚空展开使用吸入、滤波和瞬时静音，避免刺耳噪声。
- **DIO / 世界**
  - 拳击声更低沉，木大喊声与承太郎区分声线。
  - 时停音色更具压迫感，但与承太郎共用同一规则时长。

其他十一名敌人使用“基础战斗音色 + 替身属性修饰器”，例如虫群、玩偶、黏液、镜面、磁力、水流、冰冻和赌局筹码，不为每个动作创建重复录音。

## 五、连打与语音

- 连打持续 10 秒，活动时间暂停时不减少。
- 喊声触发间隔保持 300ms；实际语音样本应为极短单词，不排队播放长句。
- 承太郎：原创或授权的“欧拉”单词录音。
- DIO：原创或授权的“木大”单词录音。
- 未配置样本时使用本地语音合成回退，并持续显示字幕。
- 结尾增加独立重拳，不与循环中的普通拳声相同。
- 双方同时连打时：
  - P1 略偏左声道，P2 略偏右声道。
  - 总线自动降低单次拳击音量，防止叠加削波。

## 六、音量、暂停与无障碍

游戏内新增三个开关：

- 打击音效
- 角色语音
- 环境与待机声

规则：

- 所有总线乘以宿主 `masterVolume`。
- 静音时不创建新的 AudioNode。
- 暂停时挂起 `AudioContext`，取消语音并冻结循环声位置。
- 恢复时不补播暂停期间错过的声音。
- 离局、重开和切换模式时停止所有循环、清空语音队列。
- 所有关键语音同时显示字幕；关闭语音不关闭字幕。
- “减少动态效果”不自动静音，但关闭强烈镜头音与高频连续提示。

## 七、素材规范

- 短音效优先 `.ogg`，单声道，48kHz，16/24-bit 源文件。
- 循环音需无爆点、无明显接缝，并记录循环起止点。
- 单个短音效目标小于 100KB；角色语音目标小于 200KB。
- 不使用来源不明的动画、游戏或配音演员录音。
- 每个文件在 `packages/assets/stardust/audio/README.md` 记录：
  - 用途
  - 作者或生成方式
  - 许可状态
  - 修改记录

## 八、性能与并发

- 预加载当前对局角色、敌人和场景所需音效，不一次解码全角色库。
- 同类轻击最多同时播放 4 个；超过后丢弃最旧或最低音量实例。
- 连打拳声通过一个调度器播放，不为每次命中创建长期定时器。
- 空间声仅使用简单左右声像，不引入卷积混响。
- 所有节点在 `onended` 中断开连接。
- 页面后台、暂停和卸载时必须停止循环与定时调度。

## 九、实施阶段

### 阶段 1：事件与引擎

- 建立音频事件类型、纯映射函数和统一播放器。
- 迁移现有连打音效与语音逻辑。
- 完成暂停、静音、卸载和并发管理。

### 阶段 2：通用战斗音效

- 接入挥空、命中、格挡、受击、倒地、K.O.、复活。
- 接入入场、`FIGHT`、换人和队伍击破。
- 先使用合成音层，保证完整功能和可测试性。

### 阶段 3：角色专属表现

- 接入四名主角与三名主要首领的专属音色。
- 增加时停、火焰、剑击、绿宝石、枪击和虚空效果。
- 为其余敌人配置属性修饰器。

### 阶段 4：待机与环境

- 增加低频待机声音和场景环境。
- 调整随机间隔、音量和并发，避免持续噪声。
- 完成耳机与扬声器人工试听。

### 阶段 5：正式语音素材

- 接入项目自制或已授权的欧拉、木大及角色短句。
- 本地语音合成保留为加载失败时的回退。
- 完成素材来源与许可记录。

## 十、验证计划

### 单元测试

- 每个事件映射到正确的音层与字幕。
- 音量为零时不创建节点。
- 暂停和卸载会停止循环、语音和连打调度。
- 连打保持 10 秒与 300ms 节拍。
- 角色专属音色不会映射到错误角色。
- 同类音效并发不超过上限。

### 浏览器测试

- 用户首次交互后 AudioContext 能恢复。
- 攻击、格挡、K.O. 与复活触发对应事件。
- 暂停后不继续创建音频节点。
- 静音后字幕保留、声音停止。
- 模式切换和离局无控制台错误。

### 人工试听

- 桌面扬声器、普通耳机各试听一次。
- 检查连打 10 秒是否疲劳、削波或遮盖其他提示。
- 检查待机声音是否在 30 秒内产生明显重复感。
- 检查时停前后静音是否突兀。
- 检查手机音量较低时轻击与格挡是否仍可区分。

## 十一、完成标准

- 已实现事件清单中的所有现有玩法事件。
- 四名主角和三名主要首领具备可辨识专属音色。

- 无未释放的 AudioNode、语音队列或循环声。
- 所有外部音频素材有明确来源与许可记录。
