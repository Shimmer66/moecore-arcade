# 萌芯游乐园 UI 规范

本规范用于首页、游戏宿主和游戏外围控件。展示名为“萌芯游乐园 · MoeCore Arcade”，保留数据海壁纸与液态玻璃主题。实际实现见 `apps/web/src/features/liquid-glass/`、`App.vue`、`HomeView.vue` 和 `games/GameHost.vue`；各游戏内部场景保留独立美术。

## 玻璃与共享颜色

`platform.css` 在基础 `styles.css` 之上定义站点主题。首页及游戏工具栏使用 `LiquidGlass` 和 `data-glass` 标记；游戏底板、暂停、结算、确认弹窗及其按钮使用 `LiquidSurface`。底部导航由 `LiquidDock` 管理，外壳与选中项使用独立透镜，折射真实页面背景。

| 变量             | 当前值    | 用途       |
| ---------------- | --------- | ---------- |
| `--glass-ink`    | `#203552` | 标题与正文 |
| `--glass-muted`  | `#344f6b` | 辅助说明   |
| `--glass-accent` | `#275fa6` | 操作与强调 |

游戏内部使用各自的 scoped 样式，不为接入新玩法改写全局主题或增加全局品牌色依赖。游戏中的危险、奖励、角色与场景配色由游戏自身管理；游戏不能导入应用源码。

玻璃必须保留折射与高光，而不只是背景模糊。`LiquidSurface` 的中心保持平坦，让暂停时的游戏画面与实际坐标一致。不要用不透明底板覆盖透镜，也不要给 Dock 外层增加会截断子透镜背景采样的滤镜。

所有 `backdrop-filter` 声明保留当前顺序：先普通 blur 降级，再带折射变量的声明；每组先写 `-webkit-backdrop-filter`，最后写标准 `backdrop-filter`。这个顺序用于保留生产 CSS 中的标准声明，不能在样式清理时随意合并或调换。

WebGL 不可用或壁纸加载失败时，保留 CSS 玻璃降级与可用的页面控件。减少动态效果设置停用弹性位移，系统高对比度模式使用可辨认的边框与系统颜色。

## 页面与组件

- **首页**：保留搜索和“全部、益智、动作、文字、卡牌、多人”六个分类。空分类显示空状态与返回全部入口，分类按钮以 `aria-pressed` 表达选中状态。
- **游戏库**：桌面四列，760px 及以下两列；手机仍使用纵向玻璃卡片。主内容最大宽度为 1104px，手机首页左右各留 20px。
- **封面**：从 `@moecore/assets` 的 `ARCADE_PORTRAITS` 读取；保留消消乐、跑酷、推箱子和鲸鲸长队的既有头像，新增游戏在同一公开映射中接入素材。
- **导航**：首页 Dock 提供首页、游戏库和共创区入口，支持点击、键盘与拖动预览；游戏页由宿主提供返回、暂停、重开、全屏和减少动态效果操作。
- **游戏宿主**：保持 `LiquidGlass` 工具栏与 `LiquidSurface` 游戏底板、暂停、结算和原生 `dialog` 确认框。游戏只提供玩法内容与结果，不能复制宿主或重写全局主题。
- **文字与控件**：使用系统中文无衬线字体、清楚的可见焦点与可访问名称。主要触屏操作至少提供 44px 点击区域；新增正文避免沿用现有少量 9–11px 的辅助标签字号。

首页主要断点为 1000px、760px 和 380px；游戏可以针对棋盘与控制布局设置局部断点。游戏内部场景和专属操作区保留独立风格，外围站点主题保持一致。

## 验证

必须对生产构建验证玻璃，开发服务中的外观不能代替构建产物检查：

```bash
pnpm run build
pnpm --filter @moecore/web exec playwright test liquid-glass.spec.ts
pnpm run test:e2e
```

`liquid-glass.spec.ts` 覆盖玻璃拉伸、Dock 与面板折射、平坦中心、搜索与筛选、移动壁纸、键盘和拖动导航、减少动态效果、WebGL 与图片加载降级。检查桌面、手机和 320px 窄屏布局，确保没有横向溢出，按钮与玩法画面可见。

暂停和结算的完整焦点进入与恢复、所有游戏人工通关、真机触摸及跨浏览器兼容性仍需单独验收。命令与证据边界见[开发指南](development.md)。
